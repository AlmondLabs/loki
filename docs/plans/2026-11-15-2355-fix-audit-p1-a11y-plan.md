# The audit's accessibility findings - Plan

---

## Goal Capsule

- **Objective:** fix the major findings (P1) of the 2026-11-15 audit of the desktop UI (`.impeccable/audit/`), each a
  WCAG A or AA failure, so a person using a screen reader or the keyboard can follow a chat, see why a form failed and
  pick from a list.
- **Means:** ARIA and keyboard fixes where each finding lives, and one small part, `ThreadAnnouncer`.
- **Authority:** the Requirements, then the Key Technical Decisions.
- **Stop conditions.** Stop and ask if a fix changes what a sighted pointer user sees.
- **Execution profile:** desktop UI across `app/src`; one PR.
- **Who finishes:** `ce-work` on branch `fix/audit-p1-a11y`.

---

## Product Contract

### Requirements

- R1. A screen reader hears when the agent starts thinking, when it waits on you, and the opening of its reply when a
  turn ends (WCAG 4.1.3).
- R2. A form's error is announced when it appears: Preferences (engines, Macs, skills, providers, accounts, MCP, chat
  links), Change Folder, Welcome, New Agent, an agent's skills (WCAG 4.1.3).
- R3. The mention list, the To and Cc fields' suggestions and the Folder field's list say which entry ↑↓ are on
  (WCAG 4.1.2).
- R4. Tabbing through the Folder field leaves the folder as it was, unless you typed or chose with the arrows
  (WCAG 3.2.2, 2.1.1).
- R5. A control's name holds the words it shows: an engine's Try and Reset, the permission mode chip (WCAG 2.5.3).
- R6. The canvas's chat button says whether the chat is open and that something waits, which its dot shows only by
  colour (WCAG 4.1.2, 1.4.1).
- R7. Every skill field has a name beyond its placeholder (WCAG 1.3.1, 3.3.2).

## Planning Contract

### Key Technical Decisions

- KTD1. **One spoken line per thread, not a live log.** A `role="log"` over the transcript would read every streamed
  word. `ThreadAnnouncer` is a polite, atomic status region that is always mounted, whose words are derived from the
  thread: "Atlas is thinking", "Atlas is waiting for you", "Atlas replied: …" (the reply's first 160 characters). It
  changes only when the turn does, and a chat opened on an old reply says nothing, since a region mounted with its
  words is not read. The Thinking marker loses its own `role="status"`, so it is not said twice. The desktop's
  scroller is already a log of added rows, which reads a reply as it starts (its first words, as they stream); the
  phone's thread has none. The line says the reply once it is whole, without its quick-replies block or Markdown
  marks. (R1)
- KTD2. **Lists over a field name their highlight.** The To and Cc fields and the Folder field are comboboxes
  (`aria-expanded`, `aria-controls`, `aria-activedescendant`, options with ids). The mention list hangs from a
  textarea, which keeps its textbox role (a combobox is not allowed on one) and takes `aria-controls` and
  `aria-activedescendant`. (R3)
- KTD3. **The Folder list opens with nothing highlighted.** Opened by focus, Return and Tab leave the folder; once you
  type, the first match is highlighted as before, and the arrows highlight one. Tab then takes it and still moves on.
  (R4)
- KTD4. **Errors are alerts**, as Rename, Labels and Lanes already have them: `role="alert"` on the line that appears.
  (R2)
