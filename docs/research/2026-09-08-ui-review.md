# loki · UI/UX review and design-system audit · 2026-09-08

Method: three isolated passes, synthesised afterwards. A design review (source + live app in its own browser tabs),
a measured evidence pass (the Impeccable detector over `app/src`, plus a computed-style census of seven views at
1440×900 and 1100×700), and a code-level audit of the token system, the component vocabulary and the guard test.
Target: `app/src` (38 `.tsx`, ~10.6k lines). Branch `feat/mobile` at `4db0ae1`, working tree clean at the time.

Views seen live: desk with a widget, desks tree (⌘K), chat (⌘/), inbox (⌘2), board (⌘3), agents (⌘4),
settings (⌘5), the phone pairing screen. Not reached live: Welcome (needs zero agents), NewDesk and TaskCapture
(not opened to avoid creating things), Approval/Question cards, the paired phone views. Those were read from source.

## Anti-patterns verdict

Pass, narrowly. Nobody would say "AI made that": the drafting-table register, the brass economy and the native title
bar are deliberate and consistent. The failure is the product-register one: the same control looks different on every
screen. Five text-field styles, fourteen chip variants, seven dialog chromes, roughly twenty-five button variants.

Detector (`detect.mjs` over `app/src`, exit 2): 5 findings across 2 rules. Three `layout-transition` hits, of which
the chat panel's `width 200ms` (`chat/ChatWindow.tsx:243`) is real and the two 2px progress-bar fills are trivial.
Two `side-tab` hits: the phone Banner's 3px oxblood stripe (`phone/ui.tsx:44`) is real; the markdown blockquote rule
is a false positive. The in-page overlay found the 1px-border-plus-24px-shadow pairing on the widget frame and the
chat bubble, a "flat type hierarchy" warning (ratio 1.8:1 across seven sizes on one view), and the brass glow.

The three passes agree on: the focus ring gap, the `.loki-label` eyebrow drift, the side stripes, the NewDesk blur,
the display serif on chrome, the off-scale sizes leaking through `.ts` and `.css`, and the reduced-motion hole.

## What's working

- **One keymap, three renderings.** `shell/keymap.ts` drives the key handler, the native menu bar and Settings › keys;
  conflicts are tested. The inbox footer that switches between letters and chords is the right instinct.
- **Catch Up as a deck.** One card, one decision, a status-coloured hairline, a 2px progress bar, live merges that never
  move the current card, backoff with "nth time around", approvals that refuse to snooze. The phone keeps it mounted
  across tabs. This is the product's clearest idea and the best-executed surface.
- **Token discipline with meaning.** Brass only for what needs the human: the permission chip turns brass only for
  "unrestricted"; the board badge is muted on purpose. 1,116 `var(--loki-*)` references and zero literal colours in
  `.tsx`. The attention marks encode state in shape as well as hue, and the phone folds the status word into the row's
  accessible name.
- **Careful engineering underneath.** Transcript rows memoised, drags mutate `transform` directly with scoped
  `will-change`, ResizeObserver plus rAF coalescing in the viewport, safe-area insets threaded through the phone shell,
  15px phone inputs to stop iOS zoom, password-manager suppression on every search field.

## Priority issues

1. **[P1] Injected protocol blocks render as the human's words.** `chat/Transcript.tsx:304` runs user text through
   Markdown, so `<loci-desk>` and `<skill_content>` appear as user bubbles, the latter with twelve headings inside an
   inbox card. It lands exactly at the product's peak moment (first widget). Fix: in the row builder
   (`packages/core/src/attention/transcript.ts`) detect the wrappers and emit event rows ("desk activity · 4 gestures",
   "skill loaded · …") using the existing `⟳` details pattern.
   *Done later the same day: `extractHarnessEvents` in `packages/core/src/harness.ts` turns both blocks into event rows
   for history and the live tail; older builds' `<loci-desk>` spelling is read too. The mod needs a `/reload` to
   serve the new history rows.*
2. **[P1] Focus is invisible or off-brand almost everywhere.** Brass `:focus-visible` exists only for `.loki-rail`
   (plus two classes nothing uses). Measured: 50 tab stops with the browser's blue ring, 4 text inputs with no indicator
   at all. Fix: one global rule in `kit/tokens.css`, delete every `outline: "none"`. *Applied in this pass.*
3. **[P1] Dialogs are not modal and lists are invisible to assistive tech.** 8 `role="dialog"`, 0 `aria-modal`, no
   focus trap, no return-focus. The tree swallows Tab (`shell/DeskTree.tsx:267`); its options are pointer divs without
   `aria-activedescendant`. Board cards are `role="option"` outside any listbox and not focusable. Fix: one `Sheet`
   primitive (veil, `aria-modal`, trap, Escape, click-out, return focus) for all eight; ids plus
   `aria-activedescendant` on the tree and picker inputs; roving tabindex on board cards.
   *Done later the same day: Sheet carries aria-modal, a Tab loop, initial and return focus; the tree and picker
   inputs are comboboxes with aria-activedescendant and a live region; board cards are options in per-column
   listboxes with a roving tabindex, arrows, Space and Shift-arrows.*
4. **[P1] Widgets cannot be moved, resized or focused from the keyboard.** Title-bar drag and a pointer-only,
   `aria-hidden` grip are the only paths (`desk/WidgetFrame.tsx:157–235`). Fix: focusable frame; arrows nudge,
   shift-arrows resize, Enter focuses the camera.
   *Done later the same day: frames are focusable groups; arrows nudge 8px (Shift 32), Alt-arrows resize, Enter
   frames the camera, Escape blurs, a polite status announces the result; one ⌘Z step per press or burst.*
5. **[P1] Contrast.** `--loki-negative` on panel is 4.20:1 and is used as 12px text in ~25 places. Muted text at the
   habitual opacities fails harder: 0.6 gives 2.75:1 (board meta ×7, kbd hints, disabled send), 0.35 gives 1.74:1 (the
   widget subtitle inside the dimmed controls group). Fix: lift the negative token; never dim *text* with opacity.
   *Token and the worst opacity sites fixed in this pass.*
6. **[P1] The component vocabulary has forked.** ~25 button variants, 20 text-field variants, 14 chips, 7 dialog
   chromes, 10 status-dot sizes. Disabled is 0.5 in twelve places and 0.6 in two. Hover exists for the rail, tree rows
   and three frame buttons; the other ~110 buttons have none because inline styles cannot express it. Fix: an
   `app/src/ui/` primitive set (see the inventory below), states in CSS classes.
   *Done later the same day: `app/src/ui/` exists and every call site is on it. Nine hand-built controls
   remain by design (rail, chat bubble, tree rows, tabs, phone tab bar, switch, thumbnail ×, Welcome's
   personality radios).*
7. **[P1] Destructive actions with no confirmation or undo.** Forget phone (`settings/Phone.tsx:87`), remove skill
   (`agents/Agents.tsx:456`), disable skill (`settings/Skills.tsx:435`), archive from the tree (a notice, no undo button).
   Fix: reuse the inline alertdialog from delete-agent; give the archive notice an undo.
8. **[P1] Reduced motion is only half honoured.** The CSS rule zeroes durations but not `animation-delay`, so under
   reduced motion each widget frame sits invisible for up to 420ms and then pops (`desk/WidgetFrame.tsx:146`). Camera
   glides are JS durations (220/600/180/500ms in `desk/Surface.tsx`) and ignore the preference. *Fixed in this pass.*
9. **[P2] The idle chat panel and its footprint.** 0.6 opacity on the whole panel; at 1100px a side chat covers 38% of
   the stage. Fix: drop the opacity trick; below ~900px collapse the side chat to the centred float or the bubble.
10. **[P2] Wrong or unbound shortcut hints.** "wide (⌘⇧/)" has no keymap entry; "dictate (⌘M)" contradicts the ⌘D
    handler. The inbox footer promises single letters that the auto-focused reply box eats. Fix: derive every hint from
    `KEYMAP`; never auto-focus the reply box. *Hints fixed in this pass; the auto-focus is a product call.*
11. **[P2] `.loki-label` has become the eyebrow on everything.** 53 uses across 23 files, ~40 overriding its size. It
    heads every settings fact, section, board column, tree section, picker group, footer and chip. Keep it for
    title-block facts and frame titles; section heads become the display-17 `SectionTitle` that already exists.
12. **[P2] Display serif on chrome.** Settings nav, agents nav and tabs, two inputs use New York. design.md scopes it to
    room names. Tree rows and phone desk titles are fine.
13. **[P2] No adaptive layer on the desktop.** The only `@media` is reduced-motion. At 1100px the inbox column is sized to
    `100vw` and clips 72px on the right; board cards clip text rather than wrap; the chat leaves 312px of sheet at 1000px.
14. **[P2] Off-scale values the guard test cannot see.** 12.5px and 10px in `chat/ui.ts`; 13/14px and 0.04em tracking in
    `chat.css`; 9 and 11 passed to `AgentChip`; a ternary 13 in Settings; `theme-color` `#101014` vs `--loki-bg`
    `#12151b`; the code block background `#101014` vs `--loki-well`; the PWA icon in the dropped blue `#5b7cfa`.
    *All but the icon fixed in this pass; the test now scans `.ts`, `.css`, html and the manifest.*
15. **[P2] Copy defects.** YAML frontmatter rendered as an h2 on memory pages (`agents/Agents.tsx:365` skips
    `stripFrontmatter`); "1000k context"; the compatibility warning fires when the harness reports exactly the tested
    version; "Connect a Anthropic API key"; absolute `/Users/…` paths in tool markers; Welcome steps numbered from 0.
16. **[P2] Performance smells.** recharts and react-markdown in the first chunk (`shared-modules.ts`); `onMouseEnter →
    setIndex` re-renders all picker/tree rows; `registerActions` depends on `draft`; 49 exhaustive-deps suppressions;
    the 90px sheet shadow on a viewport-sized card that is also transform-animated.

## Cognitive load

3 of 8 checklist items fail (moderate). Chunking: footers of 7–11 hints, a keys page of ~50 rows with no search.
Minimal choices: the inbox card footer shows 6 buttons plus 2 chips. Working memory: the same action has two grammars
(`A` vs `⌘↵`) depending on whether the reply box has focus, and `⌘]` means "next desk" on the desk and "next card" in
the inbox.

## Personas

- **Alex (power user).** Types a reply, then `A`/`→` do nothing until Esc. Chat width is a two-state toggle. Tree filter
  is `includes()`; the picker silently caps at 160. No rename for desks; titles arrive as raw first messages. ⌘R is taken.
- **Jordan (first-timer).** Harness, mod, app-server, tunnel, shim, route, "no asking". The rail desk icon doubles as the
  tree toggle with no hint. Frame controls at 0.35 opacity until hover. Editable profile fields look like text.
- **Sam (screen reader, keyboard, low vision).** Everything in issues 2, 3 and 4. Hover-only pin/archive. Widget error is
  a dot with a tooltip. 9.5px tracked caps for rail and section labels. `maximum-scale=1` blocks pinch zoom on the phone.
  Agent filter chips are `role="tab"` filtering a listbox.
- **Casey (phone).** Footer actions 36px, chips 32px, "seen" 34px. Seen and pin sit in the top bar, out of the thumb
  zone. Pairing needs a 6-character code read off another screen within ten minutes. Device identity is the pairing time.

Home: `app/src/ui/`, not `kit/`. `@loki/kit` is the agent-facing widget kit aliased in `vite.config.ts`; app chrome must
not ship into that surface. Migration order by payoff: merge `chat/ui.ts` and `phone/ui.tsx` → dialogs (7 files) →
fields (14 files) → chips (8 files).

Token gaps: no spacing scale (110 distinct padding strings, 26 numeric atoms); eight control heights (28–56); four field
radii; no state tokens; no second muted for secondary text; nine motion durations; `LAYER` arithmetic (`modal + 1`) and
literal in-component z (20, 10, 8…); the type scale is not in Tailwind's `@theme`, so an agent widget using `text-sm`
gets 14px.

Tailwind: `@theme inline` maps 15 token utilities; the app uses zero of them (the only utility in use is `sr-only`).
Tailwind is there for the agent's widget files, which is legitimate, but the mapping should then also carry the type
scale, and `skills/loki/SKILL.md` should say which classes are on-scale.

Dead: `.loki-cell`/`.loki-plate` rules (no references), `className` hooks with no CSS (`loki-field` ×3,
`loki-model-chip`, `loki-menu-row`, `loki-veil`), `docs/kit.md` (referenced, does not exist), the `.loki-pulse` class
duplicated inline at 1.6s. *Removed in this pass.*

## Questions worth answering before the next build

1. If the native title bar is the only chrome, why is it the only thing that knows a desk is archived? Should the sheet
   carry that truth and a restore?
2. Is the chat a panel or a room? Idle opacity says background; centring it on an empty desk says foreground.
3. Two keyboard grammars exist for one deck because the reply box takes focus. What would the inbox be if nothing took
   focus until you asked?
4. The desks list exists three times with three chip components. Is it a component, or an idea each view reinvents?
5. Where does "room name" end and "UI label" begin for the serif?

## Recommended order

1. `harden`: issues 1, 3, 4, 7 (transcript wrappers, modal sheets, keyboard widgets, confirmations).
2. `extract`: the spacing/height/state tokens, the type scale into `@theme` (the primitive set is done).
3. `adapt`: a breakpoint layer for the desktop; 44px phone targets; the inbox width at 1100.
4. `clarify`: the jargon list, the error strings, frontmatter, "1000k", version compare.
5. `optimize`: lazy recharts/markdown, picker and tree hover re-renders, the CatchUp action effect.
6. `polish`.
